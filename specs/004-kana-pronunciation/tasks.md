## Cơ chế nạp JSON của Vite và tsconfig (cho Story 4)

Bảng sửa cách đọc là `content/overrides/speech-corrections.json`, được `src/lib/tts.ts` nhập tĩnh:

```ts
import corrections from '../../content/overrides/speech-corrections.json'
```

- **Vite**: plugin `vite:json` có sẵn biến `.json` thành module ES; dùng **default import** (không dựa vào named export). Khi `npm run build` file vào chunk chính. File nằm dưới gốc dự án nên dev server (`server.fs.strict`) cho phép đọc. Vitest dùng cùng bộ biến đổi của Vite. **Không cần sửa `vite.config.ts`.**
- **TypeScript**: `tsconfig.app.json` đặt `moduleResolution: "bundler"` nên `resolveJsonModule` bật theo mặc định, và file JSON nằm ngoài `include: ["src"]` vẫn được nạp khi có import. Đã thử ngày 2026-11-12 (TypeScript 6.0.3): tạo tạm một file JSON dưới `content/overrides/` và một file `.ts` dưới `src/lib/` import nó; `tsc -p tsconfig.app.json --noEmit` không báo lỗi; vitest import chạy được; đã xóa hai file tạm. **Kết luận: không cần sửa `tsconfig.app.json`, `tsconfig.node.json` hay `vite.config.ts`.** Nếu `npm run check`/`build` đỏ vì chính import này thì **dừng và hỏi**, không tự sửa tsconfig.
- **`tsconfig.node.json`** (`module: nodenext`, biên dịch `scripts/**`): không dính, vì `src/lib/speakable.ts` không import JSON (bảng truyền vào làm tham số) và test nội dung đọc file bằng `readFileSync` + `JSON.parse`, không `import`. `tts.ts` không bị `scripts/` import.
- **Pipeline/validate không đụng**: `scripts/content/pipeline.ts` đọc đúng ba file yaml theo đường dẫn tường minh (`overrides/pos.yaml`, `verb-groups.yaml`, `id-aliases.yaml`), không quét thư mục. Kiểm chứng bằng thực nghiệm: băm `public/content/**` (bỏ `public/content/README.md`, file duy nhất git theo dõi ở đó) và số cảnh báo của `content:validate` lúc đầu (T004, lấy sau hai lần `content:build` liên tiếp cho cùng băm) và sau khi thêm file ở Commit 4 (T072) phải giống hệt.
